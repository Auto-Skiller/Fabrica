# Pi Agent & Harness CLI Skill — pi-harness-agent

## Metadata
- **Name**: pi-harness-agent
- **What**: Comprehensive Harness Agent directive and complete command reference for the `pi` Agent CLI, enforcing CLI-authoritative management of `.pi/agent` and workspace harness sessions.
- **When**: Invoked whenever interacting with the Pi coding agent, executing harness sessions, running agent tasks, configuring agent execution flags, or managing agent skills and extensions.
- **Why**: Enforces strict CLI-authoritative isolation so that `.pi/agent` directory structure, session stores, authentication credentials, and model caches are exclusively generated and managed by the `pi` CLI itself—never manually created or modified by direct file writes.
- **Triggers**: Agent execution requests, `pi` CLI invocations, harness runner configuration, agent session management.
- **Inputs**: User prompts, tenant session IDs, model flags, skill/extension paths, environment variables.
- **Outputs**: CLI flag configurations, process execution outputs, agent response streams.

---

## 1. STRICT CLI-AUTHORITATIVE INVARIANT FOR `.pi/agent`
1. **No Manual File Creations**: The directory `.pi/agent` (and `.pi/sessions`) is strictly managed and generated by the `pi` CLI itself.
2. **Never Write directly to `.pi/agent`**: No backend script, agent code handler, or automated tool should manually create, edit, or overwrite files inside `.pi/agent` (such as `auth.json`, `models-store.json`, or `session.jsonl`).
3. **CLI Execution Only**: Any creation, session update, model store caching, or authentication token management inside `.pi/agent` MUST be handled natively by executing `pi` commands (e.g. `npx pi`, `./node_modules/.bin/pi`, or `pi`) or by instructing the agent to run them via CLI.

---

## 2. HARNESS AGENT INTEGRATION ARCHITECTURE
The system harness (`src/harness.ts` & `src/pi_runner.ts`) interfaces with the `pi` CLI by spawning `pi` process instances with tenant-isolated options:

- **Workspace Root**: `workspaces/<tenant_id>/`
- **Agent Config Directory**: `PI_CODING_AGENT_DIR=workspaces/<tenant_id>/.pi/agent`
- **Session Storage Directory**: `PI_CODING_AGENT_SESSION_DIR=workspaces/<tenant_id>/.pi/sessions`
- **Built-In Kernel Capabilities**: Loaded via `--extension Fabrica_kernel/extensions/context_injector.js` and `--extension Fabrica_kernel/extensions/registry_bridge.js`
- **Custom Workspace Capabilities**: Dynamically passed via `--skill workspaces/<tenant_id>/.pi/skills` and `--extension workspaces/<tenant_id>/.pi/extensions` (or toggled off via `--no-skills` / `--no-extensions` when tools are toggled off in the UI).

## 3. COMPLETE `pi` CLI COMMAND & FLAG REFERENCE (`pi --help`)

### Usage Syntax
```bash
pi [options] [@file...] [prompt...]
```

### Options & Flags

#### General & Model Selection
- `--provider, -pv <name>`
  - Set LLM provider (e.g. `anthropic`, `openai`, `google`, `openrouter`, `mistral`, `deepseek`, `groq`, `azure`, `bedrock`, etc.)
- `--model, -m <model>`
  - Model name or shortcut (e.g. `gemini-3.6-flash`, `claude-3-7-sonnet`, `openai/gpt-4o`, `sonnet:high`)
- `--api-key <key>`
  - Pass API key directly for the active run
- `--append-system-prompt @file`
  - Append text or file contents to the system prompt (can be used multiple times)
- `--thinking <level>`
  - Set model thinking level: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`
- `--models <patterns>`
  - Comma-separated model patterns for Ctrl+P cycling (supports globs like `anthropic/*`, `*sonnet*` and fuzzy matching)
- `--list-models [search]`
  - List available models (with optional fuzzy search)

#### Modes & Interactivity
- `--mode <mode>`
  - Output mode: `text` (default), `json`, or `rpc`
- `--print, -p`
  - Non-interactive mode: process prompt and exit
- `--verbose`
  - Force verbose startup (overrides `quietStartup` setting)
- `--offline`
  - Disable startup network operations (same as `PI_OFFLINE=1`)
- `--approve, -a`
  - Trust project-local files for this run
- `--no-approve, -na`
  - Ignore project-local files for this run
- `--help, -h`
  - Show help message
- `--version, -v`
  - Show version number

#### Session Management
- `--continue, -c`
  - Continue previous session in current workspace
- `--resume, -r`
  - Select a session to resume
- `--session <path|id>`
  - Use specific session file path or partial UUID
- `--session-id <id>`
  - Use exact project session ID, creating it if missing
- `--fork <path|id>`
  - Fork specific session file or partial UUID into a new session
- `--session-dir <dir>`
  - Directory for session storage and lookup (overrides `PI_CODING_AGENT_SESSION_DIR`)
- `--no-session`
  - Don't save session (ephemeral run)
- `--name, -n <name>`
  - Set session display name
- `--export <file>`
  - Export session file to HTML and exit

#### Tools & Capabilities
- `--no-tools, -nt`
  - Disable all tools by default (built-in and extensions)
- `--no-builtin-tools, -nbt`
  - Disable built-in tools by default, but keep extension/custom tools enabled
- `--tools, -t <tools>`
  - Comma-separated allowlist of tool names to enable (applies to built-in, extension, and custom tools)
- `--exclude-tools, -xt <tools>`
  - Comma-separated denylist of tool names to disable

#### Skills, Extensions, Templates & Themes
- `--skill <path>`
  - Load a skill file or directory (can be used multiple times)
- `--no-skills, -ns`
  - Disable skills discovery and loading
- `--extension, -e <path>`
  - Load an extension file (can be used multiple times)
- `--no-extensions, -ne`
  - Disable extension discovery (explicit `-e` paths still work)
- `--prompt-template <path>`
  - Load a prompt template file or directory (can be used multiple times)
- `--no-prompt-templates, -np`
  - Disable prompt template discovery and loading
- `--theme <path>`
  - Load a theme file or directory (can be used multiple times)
- `--no-themes`
  - Disable theme discovery and loading
- `--no-context-files, -nc`
  - Disable `AGENTS.md` and `CLAUDE.md` discovery and loading

## 5. BUILT-IN TOOL NAMES

- `read`: Read file contents
- `bash`: Execute bash commands
- `edit`: Edit files with find/replace
- `write`: Write files (creates/overwrites)
- `grep`: Search file contents (read-only, off by default)
- `find`: Find files by glob pattern (read-only, off by default)
- `ls`: List directory contents (read-only, off by default)

## 6. EXAMPLES & USAGE PATTERNS

### Interactive Mode
```bash
pi
pi "List all .ts files in src/"
pi @prompt.md @image.png "Analyze these files"
```

### Non-Interactive Mode (Single Execution)
```bash
pi -p "List all .ts files in src/"
```

### Session Continuation & Naming
```bash
pi --continue "What did we discuss earlier?"
pi --name "Refactor authentication system"
```

### Provider & Model Selection
```bash
pi --provider openai --model gpt-4o-mini "Help refactor this code"
pi --model openai/gpt-4o "Help refactor this code"
pi --model sonnet:high "Solve complex architectural issue"
pi --models claude-sonnet,claude-haiku,gpt-4o
```

### Tool Filtering
```bash
# Read-only mode (prevent accidental file modifications)
pi --tools read,grep,find,ls -p "Review code in src/"

# Disable specific tool
pi --exclude-tools ask_question
```

### Session Export
```bash
pi --export ~/.pi/agent/sessions/session.jsonl output.html
```
